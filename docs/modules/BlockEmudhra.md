# Block Emudhra
封禁 Emudhra 证书
分类：Web，位于 TcpKiller 下方。

## 需求
- 安全级别：常规模块，但会持久修改本机证书信任策略
- 权限需求：管理员
- 驱动依赖：否
- 联网需求：是
- 开发状态：稳定/常规
- 版本属性：Free / Pro 均可用

当前客户端没有管理员权限时，模块需求图标优先显示管理员权限提示，而不是联网图标。System / TrustedInstaller 的权限不足提示也优先显示，规则统一覆盖 Dropdown、Neverlose、模块库和搜索结果。

## 介绍
移植自 `Block-EmudhraCompromisedCA.ps1`，将指定清单内的 Emudhra 中间证书加入 Windows 本机的“不受信任的证书”存储（`LocalMachine\Disallowed`）。不删除受信任根证书，也不按发行者名称批量封禁其他证书。

点击开启后提交一次后台任务，模块开关立即关闭，不保存开启状态。任务执行期间再次点击不会重复创建任务。需要以管理员身份运行客户端。

模块原始英文名称为 `Block Emudhra`。旧 Profile 中的 `BlockEmudhra` 配置仍可加载；新旧名称同时存在时优先使用新名称下的配置。内部枚举、源码文件名和日志前缀 `[BlockEmudhra]` 保持不变。

## 执行流程
1. 通过 HTTPS 下载 `https://emudhra.we-have-a-problem.com/impacted-intermediates.json`，始终启用 TLS 证书及主机名校验，使用 8 秒连接超时、15 秒总超时及 2 MiB 响应上限。
2. 对原始响应计算 SHA-256，必须与脚本固定的 `F67B3ABE9B4879F4E91874ED041BECCD71257F1DB41C588C724CCF12AA90C59E` 完全一致。不自动信任在线提供的新哈希，也不提供跳过校验的选项。
3. 解析清单并完整验证全部 PEM / X.509 证书后，才打开本机可写证书存储。下载、哈希或解析失败时不导入任何证书。
4. 逐项加入 `LocalMachine\Disallowed`，保留已经存在的证书及其属性，统计新增与已封禁数量。
5. 在客户端通知及 `CLIENT.LOG` 的 `[BlockEmudhra]` 记录中报告结果。写入中途失败时报告部分成功数量，不撤销已经完成的封禁。

## 配置项
- Notify（通知）：布尔，默认 `true`。显示任务开始及成功通知；失败和重复执行提示始终显示，结果日志不受此项影响。

仅一个通知选项，无额外分组或条件隐藏。

## 注意事项
- 这是一次性系统配置操作，不是持续运行的网络过滤器。模块开关关闭、客户端退出和系统重启都不会撤销已完成的封禁。
- 相关证书链可能因此不再被 Windows 信任，导致依赖它们的网站、签名验证或软件功能不可用。作用范围是 Windows 本机证书存储，不保证覆盖使用独立证书库的应用。
- 远端清单若变更，即使内容合理也会因哈希不匹配而拒绝导入；应先人工审核公告和新清单，再更新客户端中的固定哈希。
- 如确需恢复信任，请先核实风险和清单，在 `certlm.msc` 的“不受信任的证书 → 证书”中按证书指纹精确核对后人工处理。不要清空整个存储，也不要移除原本就被 Windows、组织策略或其他安全工具封禁的证书。
- 失败后的重新执行会跳过已有证书，可继续补齐此前尚未导入的项目。
